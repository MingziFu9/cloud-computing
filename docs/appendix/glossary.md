# 附录 D 术语表

本表按章节顺序列出本书的主要术语，每个术语给出英文名称、简明定义和例子。正文中带虚线下划线的术语，把鼠标停在上面就能看到定义，点击可以跳到本表。

通用术语的译名和定义以本系列教材共用的《系列公共术语表》为准，各书保持一致。

## 第 1 章 云计算基础

| 术语 | 英文 | 定义 | 例子 |
|---|---|---|---|
| <span id="g-云计算"></span>云计算 | Cloud Computing | 通过网络按需获取可配置的计算、存储、网络等资源，并按使用量付费的服务模式 | 在阿里云上租一台服务器，用几小时付几小时的钱 |
| <span id="g-虚拟化"></span>虚拟化 | Virtualization | 把一台物理计算机的 CPU、内存、存储等资源抽象成多台相互隔离的虚拟计算机的技术 | 一台物理服务器上同时运行 10 台虚拟机 |
| <span id="g-分布式计算"></span>分布式计算 | Distributed Computing | 让网络中多台独立的计算机协同工作，像一个系统一样完成同一个计算任务 | 用上百台服务器一起统计全网搜索日志 |
| <span id="g-资源调度"></span>资源调度 | Resource Scheduling | 按一定策略把计算、存储等资源分配给用户的任务，以提高利用率并保证服务质量 | 把新建的虚拟机放到负载最低的物理服务器上 |
| <span id="g-多租户"></span>多租户 | Multi-tenancy | 多个用户共享同一套基础设施或软件，彼此的数据和配置相互隔离 | 成千上万家企业同时使用同一个在线办公 SaaS |
| <span id="g-弹性伸缩"></span>弹性伸缩 | Auto Scaling | 根据负载自动增加或减少计算资源 | 促销时自动从 2 台服务器扩到 20 台，结束后缩回 |
| <span id="g-按需付费"></span>按需付费 | Pay-as-you-go | 按实际使用的资源量和时长计费，不用一次性购买硬件 | 云服务器按小时计费，关机释放后不再收费 |
| <span id="g-基础设施即服务"></span>基础设施即服务 | IaaS | 云服务商提供服务器、存储、网络等基础资源，用户自己安装操作系统以上的软件 | 阿里云 ECS、AWS EC2 |
| <span id="g-平台即服务"></span>平台即服务 | PaaS | 云服务商在基础设施之上再提供运行环境和中间件，用户只需部署应用代码 | 阿里云函数计算、云数据库 |
| <span id="g-软件即服务"></span>软件即服务 | SaaS | 云服务商提供可以直接使用的完整软件，用户通过浏览器或客户端使用 | 钉钉、腾讯文档、企业微信 |
| <span id="g-公有云"></span>公有云 | Public Cloud | 由第三方云服务商建设、通过互联网向公众提供的云服务 | 阿里云、腾讯云、华为云 |
| <span id="g-私有云"></span>私有云 | Private Cloud | 为一个组织单独建设、只供其内部使用的云平台 | 银行在自己的数据中心建设的云平台 |
| <span id="g-混合云"></span>混合云 | Hybrid Cloud | 把公有云和私有云结合使用，数据和应用可以在两者之间流动 | 核心数据放私有云，促销流量用公有云扩容 |
| <span id="g-社区云"></span>社区云 | Community Cloud | 由有共同需求的多个组织共同建设和使用的云平台 | 一个地区的多所高校共建的教育云 |

## 第 2 章 云计算核心技术

| 术语 | 英文 | 定义 | 例子 |
|---|---|---|---|
| <span id="g-虚拟机监视器"></span>虚拟机监视器 | Hypervisor | 运行在硬件和虚拟机之间、负责创建和管理虚拟机的软件层 | KVM、VMware ESXi、Xen |
| <span id="g-容器"></span>容器 | Container | 共享宿主机操作系统内核、把应用及其依赖打包在一起运行的轻量级隔离环境 | 用 Docker 运行的 Nginx 网站 |
| <span id="g-快照"></span>快照 | Snapshot | 记录某一时刻虚拟机或磁盘的状态，以便日后回滚到这一时刻 | 升级系统前打一个快照，失败后一键恢复 |
| <span id="g-虚拟机迁移"></span>虚拟机迁移 | VM Migration | 把运行中的虚拟机从一台物理主机搬到另一台主机，热迁移时业务不中断 | 物理服务器维护前，把上面的虚拟机热迁移走 |
| <span id="g-对象存储"></span>对象存储 | Object Storage | 以“对象”为单位、通过 HTTP 接口存取数据的存储方式，每个对象包含数据、元数据和唯一标识 | 阿里云 OSS、Amazon S3 存放图片和视频 |
| <span id="g-文件存储"></span>文件存储 | File Storage | 以目录和文件的层级结构组织数据，可被多台服务器同时挂载访问 | 多台 Web 服务器共享同一个 NAS 目录 |
| <span id="g-块存储"></span>块存储 | Block Storage | 把存储空间划分为固定大小的块，以裸磁盘的形式提供给服务器使用 | 云服务器挂载的云盘 |
| <span id="g-纠删码"></span>纠删码 | Erasure Coding | 把数据切成若干块并计算出校验块，丢失部分块后仍能恢复数据的冗余技术 | 4+2 纠删码最多可同时坏 2 块盘，存储利用率约 67% |
| <span id="g-MapReduce"></span>MapReduce | MapReduce | 把大数据处理分成 Map（分别处理）和 Reduce（汇总）两个阶段并行执行的编程模型 | 统计海量网页中每个词出现的次数 |
| <span id="g-Spark"></span>Spark | Apache Spark | 把中间结果保存在内存中的分布式计算框架，比 MapReduce 更快 | 用 Spark 分析电商一天的点击日志 |
| <span id="g-软件定义网络"></span>软件定义网络 | SDN | 把网络的控制平面和数据转发平面分离，用软件集中控制网络 | 在控制台点几下就建好一个虚拟网络 |
| <span id="g-私有网络"></span>私有网络 | VPC | 在云上为用户划出的一块逻辑隔离的网络空间，用户可自定义网段、子网和路由 | 为一个项目建 VPC 192.168.0.0/16 |
| <span id="g-弹性-IP"></span>弹性 IP | Elastic IP | 可以单独申请、随时绑定到不同云资源上的公网 IP 地址 | 服务器故障时，把弹性 IP 换绑到备用服务器 |
| <span id="g-安全组"></span>安全组 | Security Group | 云服务器的虚拟防火墙，用规则控制哪些流量可以进出实例 | 入方向放行 TCP 22 和 80 端口 |
| <span id="g-等级保护制度"></span>等级保护制度 | Classified Protection of Cybersecurity | 我国按重要程度对网络和信息系统分级实施安全保护的制度，2.0 标准把云计算等新技术纳入保护范围 | 政务系统上云要通过等保三级测评 |
| <span id="g-桌面云"></span>桌面云 | Desktop Cloud | 把桌面操作系统放在云端运行，用户通过终端远程使用 | 学校机房用瘦客户机连接云端的 Windows 桌面 |

## 第 3 章 云计算平台与工具

| 术语 | 英文 | 定义 | 例子 |
|---|---|---|---|
| <span id="g-抢占式实例"></span>抢占式实例 | Spot Instance | 价格大幅低于按量付费、但可能被云平台随时回收的云服务器 | 用抢占式实例跑可以中断的批量计算任务 |
| <span id="g-云数据库"></span>云数据库 | Cloud Database | 由云平台负责安装、备份、高可用等运维工作的托管数据库服务 | 阿里云 RDS MySQL |
| <span id="g-消息队列"></span>消息队列 | Message Queue | 在应用之间暂存和转发消息的中间件，实现异步通信和解耦 | 下单后把“发短信”消息放进队列，由短信服务慢慢处理 |
| <span id="g-API-网关"></span>API 网关 | API Gateway | 所有后端服务的统一入口，负责路由、鉴权、限流和监控 | 手机 App 的请求都先经过 API 网关再转给各个微服务 |
| <span id="g-函数计算"></span>函数计算 | Function Compute | 以函数为单位运行代码、按调用次数和执行时间计费的 Serverless 服务 | 用户上传图片时自动触发函数生成缩略图 |
| <span id="g-模型即服务"></span>模型即服务 | MaaS | 把训练好的人工智能模型以 API 等形式提供给用户、按调用量计费的服务模式 | 调用阿里云百炼上的通义千问 API |
| <span id="g-客户关系管理"></span>客户关系管理 | CRM | 管理客户信息、销售机会和客户服务的软件系统 | Salesforce、纷享销客 |
| <span id="g-企业资源计划-ERP"></span>企业资源计划 / ERP | ERP | 统一管理企业财务、采购、库存、生产等资源的软件系统 | 用友、金蝶的云 ERP |
| <span id="g-基础设施即代码"></span>基础设施即代码 | IaC | 用配置文件描述服务器、网络等基础设施，并由工具自动创建和管理 | 用 Terraform 文件一键创建 3 台云服务器 |
| <span id="g-Terraform"></span>Terraform | Terraform | HashiCorp 公司的开源基础设施即代码工具，可管理多家云平台的资源 | 用同一套写法创建阿里云和 AWS 的资源 |
| <span id="g-Ansible"></span>Ansible | Ansible | 通过 SSH 批量配置服务器的开源自动化工具，被管理的机器不需要安装代理 | 一条命令给 100 台服务器安装 Nginx |
| <span id="g-持续集成"></span>持续集成 | CI | 开发者频繁提交代码，每次提交都自动构建和测试，尽早发现问题 | 提交代码后 GitHub Actions 自动运行单元测试 |
| <span id="g-持续交付"></span>持续交付 | CD | 测试通过的代码自动部署到测试环境；持续交付上线前需人工批准，持续部署则自动上线 | 测试通过后自动发布到生产服务器 |

## 第 4 章 云计算应用与实践

| 术语 | 英文 | 定义 | 例子 |
|---|---|---|---|
| <span id="g-LAMP"></span>LAMP | LAMP | Linux、Apache、MySQL、PHP 四种开源软件组成的经典网站运行环境 | 实验 4-1 的留言板网站 |
| <span id="g-SSL-证书"></span>SSL 证书 | SSL Certificate | 证明网站身份并启用 HTTPS 加密传输的数字证书 | 浏览器地址栏中的小锁图标 |
| <span id="g-数据湖"></span>数据湖 | Data Lake | 以原始格式集中存放各种结构化和非结构化数据的存储架构 | 把日志、图片、数据库导出文件都放进对象存储统一分析 |
| <span id="g-微服务"></span>微服务 | Microservices | 把一个应用拆成多个可以独立开发、部署和扩展的小服务的架构 | 电商拆成用户、订单、商品、支付等服务 |
| <span id="g-Dockerfile"></span>Dockerfile | Dockerfile | 描述如何一步步构建 Docker 镜像的文本文件 | `FROM python:3.9-slim` 开头的构建脚本 |
| <span id="g-Kubernetes"></span>Kubernetes | Kubernetes | 开源的容器编排平台，自动完成容器的部署、扩缩容和故障恢复 | 让 3 个副本的网站服务始终保持运行 |
| <span id="g-Docker-Compose"></span>Docker Compose | Docker Compose | 用一个 YAML 文件定义并一次启动多个容器的工具 | `docker compose up -d` 同时启动网站和 Redis |
| <span id="g-政务云"></span>政务云 | Government Cloud | 基于云计算技术、专门为电子政务打造的信息化基础设施服务平台 | 浙江省政务云 |
| <span id="g-信创"></span>信创 | IT Application Innovation | 信息技术应用创新，用国产 CPU、操作系统、数据库等替代国外产品，实现安全可控 | 基于鲲鹏 CPU 和麒麟操作系统的信创政务云 |
| <span id="g-两地三中心"></span>两地三中心 | Two Sites Three Centers | 在同城建设生产中心和灾备中心、在异地再建一个灾备中心的容灾架构 | 医院核心系统的“两地三中心”云架构 |
| <span id="g-工业云"></span>工业云 | Industrial Cloud | 面向制造业、整合工业生产全流程资源的云服务平台 | 美的工业云 |
| <span id="g-数据即服务"></span>数据即服务 | DaaS | 把经过清洗、标注、分析的数据作为服务提供给用户的商业模式 | 云厂商向企业提供行业数据接口 |

## 第 5 章 未来趋势与职业发展

| 术语 | 英文 | 定义 | 例子 |
|---|---|---|---|
| <span id="g-边缘计算"></span>边缘计算 | Edge Computing | 在靠近数据源头的网络边缘就近处理数据，以降低延迟、节省带宽 | 路口的边缘节点直接识别闯红灯并控制信号灯 |
| <span id="g-物联网"></span>物联网 | IoT | 通过传感器和网络把各种物体连接起来，实现信息交换和智能控制 | 智慧农场的温湿度传感器 |
| <span id="g-移动边缘计算-MEC"></span>移动边缘计算 / MEC | MEC | 在离用户最近的无线接入网中部署计算和存储能力的边缘计算方案 | 运营商在 5G 基站附近部署的边缘节点 |
| <span id="g-无服务器计算"></span>无服务器计算 | Serverless | 开发者只编写业务代码，服务器的部署、运维和伸缩全部由云平台负责的计算模式 | 把小程序后端写成函数部署到函数计算 |
| <span id="g-函数即服务"></span>函数即服务 | FaaS | Serverless 的主要形式，以函数为单位部署代码，事件触发执行、按调用计费 | AWS Lambda、阿里云函数计算 |
| <span id="g-冷启动"></span>冷启动 | Cold Start | 函数长时间未被调用后再次触发时，需要重新创建运行环境，导致响应变慢 | 隔了半小时再访问，第一次请求慢了几百毫秒 |
| <span id="g-大模型"></span>大模型 | Large Model | 参数规模巨大、在海量数据上预训练的人工智能模型 | GPT-4、通义千问、DeepSeek |
| <span id="g-Transformer"></span>Transformer | Transformer | 2017 年提出的基于自注意力机制的神经网络架构，是当今大模型的基础 | GPT、BERT 都采用 Transformer 架构 |
| <span id="g-检索增强生成"></span>检索增强生成 | RAG | 先从知识库中检索相关资料，再交给大模型生成回答的技术 | 企业内部问答系统根据员工手册回答问题 |
| <span id="g-DevOps"></span>DevOps | DevOps | 打通开发和运维、通过自动化工具实现快速、可靠交付的理念和实践 | DevOps 工程师搭建 CI/CD 流水线 |
