# 3.3 PaaS 层服务 {#33}

!!! info "学前导读"

    PaaS 层服务就是云上的“精装房”：水电、家具都配好了，开发者拎包入住，只管写自己的程序。本节介绍两类最常用的 PaaS：

    1. **云中间件**（3.3.1）：[消息队列](../../appendix/glossary.md#g-消息队列 "在应用之间暂存和转发消息的中间件，实现异步通信和解耦"){ .term }像快递驿站，生产者把消息放进去，消费者按自己的节奏来取，两边不必同时在线；[API 网关](../../appendix/glossary.md#g-API-网关 "所有后端服务的统一入口，负责路由、鉴权、限流和监控"){ .term }像大楼的前台，所有访客先在这里登记、验证，再被引导到对应的部门。
    2. **应用托管与弹性伸缩**（3.3.2）：容器服务帮你管理一大群容器，[函数计算](../../appendix/glossary.md#g-函数计算 "以函数为单位运行代码、按调用次数和执行时间计费的 Serverless 服务"){ .term }则连服务器都不用管，代码按调用次数计费。

    消息队列一节的命令以 AWS 为例，阿里云对应的产品是消息队列 RocketMQ 版、轻量消息队列（原 MNS）等，用法相似。

## 3.3.1 云中间件的使用 {#331}

### 3.3.1.1 消息队列创建 {#3311}

创建消息队列需要指定队列的名字：

```text
$ aws sqs create-queue --queue-name url2png
{
    "QueueUrl": "https://queue.amazonaws.com/878533158213/url2png"
}
```

返回的 QueueUrl 要保存好。

### 3.3.1.2 消息队列使用 {#3312}

利用弹性负载均衡（elastic load balancing，ELB）实现同步解耦是比较容易的，不需要修改代码。但对于异步解耦，必须调整代码来使用消息队列。

消息队列有一个头和一个尾。从头部读取信息时，可以向尾部添加新消息，这样可以使消息的生产和消费解耦。即使暂无读取操作，新消息仍可被放入队列中，此时消息队列发挥了缓冲区的作用。为了防止消息队列无限增长，消息只能保存一段时间。如果从消息队列中消费消息，则必须确认已经成功地处理了消息，并将其从队列中永久删除。

### 3.3.1.3 API 网关的使用 {#3313}

#### 1. API 网关功能介绍

（1）路由转发：API 网关能够将请求精准转发至目标服务。在微服务架构里，结合服务注册中心，调用方仅需知晓 API 对外暴露的接口，便可访问后端服务。

（2）负载均衡：当同一服务存在多个实例时，API 网关会依据特定的调度策略，决定调用哪个实例，实现流量的合理分配。

（3）稳定性保障：具备限流熔断功能，可对客户端的访问次数与频率进行有效控制。配置流量阈值，一旦达到该阈值，API 网关能直接拦截请求。此外，还能实现 API 变更发布的灰度、回滚以及监控功能，确保系统稳定运行。

（4）安全管控：实现统一鉴权，无论是内网接口还是其他接口，都能执行身份认证鉴权逻辑，对用户安全认证进行统一管理。同时，可进行数据加解密操作，并对敏感数据实施脱敏处理，全方位保障数据安全。

（5）协议转换：作为流量入口，API 网关能够通过协议转换，整合基于不同风格和技术实现的微服务，为外部客户端提供统一的服务接口。

（6）API 配置管理：可针对不同业务的 API 和服务进行配置与管理，提供基本信息配置以及 API 文档生成等后台管理功能，方便开发与维护。

#### 2. 选择合适的 API 网关产品

根据自身业务需求，综合考虑功能完整性、性能、易用性、扩展性、社区支持以及厂商服务等多方面因素，选择合适的 API 网关产品。例如，可选用 Kong、Apache APISIX、Spring Cloud Gateway 等开源产品，或者阿里云、腾讯云、华为云等云服务提供商的商业 API 服务。

#### 3. 部署 API 网关

（1）硬件选型与架构设计：依据业务规模和性能要求，挑选合适的硬件设备或云服务器实例。大型企业或互联网公司可采用高性能服务器构建集群，以满足高并发需求；中小企业则可选择公有云平台提供的云服务器实例，经济实惠。同时，设计合理的架构，如多节点集群部署、主备模式等，保障系统的高可用性和负载均衡。

（2）安装与配置：依照所选 API 网关产品的安装指南，在服务器上进行安装与配置操作。相关操作涵盖设置 API 端口、配置后端服务地址、定义路由规则等基本参数，以及根据安全需求设置身份验证、加密通信等安全相关配置。

#### 4. 配置 API 网关

（1）定义路由规则：明确规定哪些请求应被转发至哪些后端服务。可依据请求的 URL 路径、域名、HTTP 方法等条件进行匹配，将匹配的请求转发至对应的服务地址和端口。

（2）设置负载均衡策略：选取适宜的负载均衡算法，如轮询、随机、最少连接数等，实现对后端服务实例流量的合理分配，并且可根据服务的健康状况和实时负载情况进行动态调整。

（3）配置安全策略：启用身份验证和授权机制，如 API 密钥、OAuth 2.0、JWT 等，确保只有合法客户端能够访问 API。设置访问控制列表，对不同用户或用户组的访问权限进行精细化管理。此外，还可配置数据加密、防止 SQL 注入等安全措施。

（4）调整性能相关参数：根据业务需求和系统性能表现，对 API 网关的各项性能参数进行优化。例如，调整连接超时时间、请求缓冲区大小、线程池大小等，提升 API 网关的处理能力和响应速度。

（5）测试与优化：完成配置后，全面开展功能测试、性能测试和安全测试等。依据测试结果，对 API 网关的配置进行优化与调整，确保其稳定、高效、安全运行。

#### 5. API 网关的应用场景

（1）微服务架构中的流量入口：在微服务架构体系中，API 网关作为所有服务的流量入口，将系统内部架构进行封装，为调用方提供定制化 API，集中处理鉴权、监控、负载均衡、协议转化等非业务功能。

（2）函数工作流服务开放：API 网关可将无服务器服务（如函数工作流服务）作为后端服务开放给合作伙伴。合作伙伴能够借此快速构建后端业务逻辑处理，并通过 API 网关的标准 API 接口进行访问，实现并发能力的线性扩展。

（3）API 管理：在 API 管理工作中，API 网关处于核心地位，通过流量管理机制，控制传入请求的速率和数量，确保系统达到最佳性能和资源利用率最大化。它能够依据流量模式和工作负载需求，动态扩展基础架构资源，助力企业优化资源利用并降低成本。

（4）云原生中间件：作为云原生中间件的重要组成部分，API 网关可聚合系统对外的服务，封装服务内部架构，在认证、鉴权、流量管控等业务领域发挥关键作用，所有对外访问统一通过 API 网关进行。

## 3.3.2 应用托管与弹性伸缩 {#332}

应用托管与弹性伸缩是现代云计算中的重要技术，能够帮助企业高效管理资源、降低成本并提升应用的可用性和性能。容器服务和函数计算是实现应用托管与弹性伸缩的两种常见方式。

### 3.3.2.1 容器服务 {#3321}

容器服务是一种基于容器技术的应用托管解决方案，通过容器化的方式部署和管理应用，具有轻量级、高效、可移植性强等特点。常见的容器服务包括阿里云容器服务 Kubernetes 版（ACK）、AWS 弹性容器服务（ECS）和腾讯云容器服务等。

（1）弹性伸缩：容器服务通常支持多种弹性伸缩策略，以应对业务负载的变化。

（2）水平伸缩：根据 Pod 的资源使用情况（如 CPU、内存）自动调整 Pod 的副本数量。

（3）垂直伸缩：调整单个 Pod 的资源分配（如 CPU、内存），而不改变 Pod 的副本数量。

（4）定时伸缩：基于定时任务进行伸缩，适用于业务流量有明显高峰时段的场景。

（5）事件驱动伸缩：基于事件源（如队列长度）进行伸缩，适用于事件驱动的离线作业场景。

适用场景：适用于需要长期运行、复杂部署和管理的应用，如微服务架构、[持续集成](../../appendix/glossary.md#g-持续集成 "开发者频繁提交代码，每次提交都自动构建和测试，尽早发现问题"){ .term }/持续部署等。

### 3.3.2.2 函数计算 {#3322}

函数计算是一种无服务器计算服务，用户只需定义并上传代码，无须管理服务器。当特定事件触发时，函数计算会自动执行代码，并根据负载情况进行弹性伸缩。

函数计算的弹性伸缩主要基于以下机制。

（1）实例并发度：根据实例的并发度进行伸缩。用户可以设置最小和最大实例数，并配置目标追踪策略。

（2）自动触发：当函数调用量增加时，系统自动增加实例数量以满足需求；当调用量减少时，自动减少实例数量以节省资源。

（3）适用场景：适用于事件驱动、短时任务、按需执行的应用，如数据处理、API 网关等。容器服务和函数计算都是实现应用托管与弹性伸缩的有效方式，但各有适用场景和优缺点。企业可以根据自身业务需求、技术栈和运维能力选择合适的解决方案。对于复杂、长期运行的应用，容器服务是更好的选择；而对于轻量级、事件驱动的任务，函数计算更具优势。
