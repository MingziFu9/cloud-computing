# 4.1 云计算应用案例

## 在云上搭一个网站：七步

- 选择云服务商
- 配置云服务器 → 配置云存储 → 设置云数据库
- 开发网站代码 → 部署到云服务器
- 域名绑定和 **SSL 证书**（网址变成 https）

::: notes
每一步对应一种云服务：ECS、OSS、RDS、域名和证书服务。图片、视频等静态文件放对象存储，可以设为“公共读”。
:::

- 请求依次经过 DNS 解析、安全组、云服务器、云数据库

|---|---|---|

## 云上数据分析平台：三步

| 步骤 | 常用工具与服务 |
|---|---|
| 数据上传 | Kafka、Flume、SDK |
| 数据存储 | 云数据库 RDS、对象存储 OSS、HDFS、数据湖 |
| 数据分析 | Spark、Flink、数据仓库、BI 工具 |

::: notes
工具名称多，知道它们分别属于采集、存储、分析哪一步即可，不必记忆。
:::

## 用容器部署微服务：五步

- 选择容器化平台：小项目 Docker，大项目 Kubernetes
- 按业务域拆分微服务
- 用 **Dockerfile** 构建镜像
- 配置容器化平台：Kubernetes 或 Docker Compose 编排
- 用 CI/CD 自动部署

## 构建并运行镜像

```bash
docker build -t my-python-app .         # 构建镜像
docker run -d -p 4000:80 my-python-app  # 运行容器
docker compose up -d --build            # 启动多个容器
docker compose ps                       # 查看状态
docker compose down                     # 停止并删除
```

::: notes
-d 后台运行，-p 4000:80 把主机 4000 端口映射到容器 80 端口；docker compose 按 docker-compose.yml 一次管理多个容器。Dockerfile 里的 EXPOSE 80 说明容器内的程序监听 80 端口。docker rmi 删除的是镜像，删除容器用 docker rm。
:::

# 4.2 云计算行业应用

## 看行业应用的四个问题

- 这个行业的“云”叫什么，有什么特点？
- 怎么建：自己建、买服务，还是混合？
- 建成什么样：分哪几层？
- 有哪些真实的例子？

## 政务云的三种建设模式

| 模式 | 做法 | 适合 |
|---|---|---|
| 集中统建型 | 政府自行投资、建设和运维 | 省级，数据安全要求极高 |
| 购买服务型 | 委托云服务商建设、运营和维护 | 区县 |
| 混合云模式 | 核心敏感数据自建，公共服务用公有云 | 敏感业务与公共服务分离 |

::: notes
政务云依托政务内网、政务外网和部门专网。涉密信息系统在政务内网，不在政务外网。信创政务云强调国产化和安全可控。
:::

## 各行业为什么用云

| 行业 | 用云解决的问题 |
|---|---|
| 电商 | 应对“双 11”等流量洪峰 |
| 教育 | 支撑在线教学、资源共享 |
| 医疗 | 病历和影像共享、灾备 |
| 制造 | 连接工业设备与供应链 |

::: notes
医疗灾备中的 RPO 是恢复点目标，即最多允许丢失多长时间的数据；RTO 是恢复时间目标。
:::

# 4.3 云计算与大数据

## 一对好搭档

- 大数据：数据太多，一台机器装不下、算不动
- 云计算：按需提供成千上万台机器
- 云计算是大数据的**基础架构**
- 大数据反过来拉动云计算的需求和创新

## 云计算为大数据提供什么

- 强大的计算能力
- 分布式存储和处理
- 资源的弹性伸缩
- 高可用性和容错性
- 数据安全，以及更低的成本

## 大数据安全与合规

- 建立清晰的数据管理策略
- 选择合适的云服务商
- 数据**加密**与**访问控制**
- 跨境数据传输符合法规
