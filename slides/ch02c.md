# 2.4 云网络技术

## 写字楼里的很多家公司

- 大家共用电梯和走廊 = 物理网络
- 每家有自己的门禁和分机 = 虚拟网络
- A 公司的服务器看不到 B 公司的
- 云网络：在物理网络之上“画”出一张张虚拟网络

## 两项网络关键技术

- **SDN**（软件定义网络）：把网络的“大脑”和“手脚”分开
  - 控制器集中决定数据怎么走
  - 交换机只负责按规则转发
- **Overlay**（如 VXLAN）：在已有网络上叠加一层虚拟网络

## 私有网络与弹性 IP

- **私有网络 VPC**：自己的隔离网络，可以自定义 IP 地址范围和子网
- **弹性 IP**：可以随时换绑的公网地址
- 服务器坏了，把弹性 IP 换绑到新服务器，用户无感
- 记住两句话：VPC = 自己的局域网，弹性 IP = 可换绑的公网地址

!sim vpc-builder
- 拖入子网、云服务器、交换机、弹性 IP
- 让外网用户能访问网站，数据库却不暴露在公网

## 虚拟网元与运维

- **分布式虚拟交换机**：连接同一主机和不同主机上的虚拟机
- **边界虚拟路由器 / 交换机**：连接虚拟网络和外部网络
- **可视化**：把复杂的虚拟网络画成拓扑图
- **运维**：监控流量，快速定位故障

# 2.5 云安全技术

## 银行与保险柜

- 钱存进银行，不用自己守保险柜
- 但银行卡密码要自己保管
- 云服务商：机房、硬件、平台的安全
- 用户：自己的账号、配置和数据
- 这就是**责任共担**

## 云安全的发展

- 2009 年：云安全联盟 CSA 成立，发布首个云安全指南
- 2010 年：CSA 提出云控制矩阵
- 2023 年：我国修订 GB/T 31168—2023
- 近年：AI 安全、数据安全成为新重点

## 常见的云安全问题

- 安全架构和策略缺失
- **数据泄露**：存储桶设成“公开”
- 恶意内部人员
- **配置错误**：数据库端口对全网开放
- **身份访问不足**：密码太简单、权限太大
- API 风险

::: notes
多数云上数据泄露不是黑客多厉害，而是用户自己配置出错。结合教材 2.5.2 的真实案例讲。
:::

## 云安全的主要威胁

| 威胁 | 一句话 |
|---|---|
| 拒绝服务攻击 | 用海量请求把服务压垮 |
| 恶意中介攻击 | 在用户和云之间截获、篡改通信 |
| 流量窃听 | 偷听传输中的数据 |
| 授权不足攻击 | 利用过宽的权限越权访问 |
| 虚拟化攻击 | 从一台虚拟机攻击宿主机或其他虚拟机 |

# 2.6 桌面云技术

## 桌上的小盒子

- 学校机房、银行柜台、医院诊室常见**瘦终端**
- Windows 桌面其实运行在机房的服务器上
- 终端只负责显示画面、接收键盘鼠标
- 好处：集中管理、数据不落地

## 三种桌面云架构

| 架构 | 在哪里算 | 终端 | 断网能用吗 |
|---|---|---|---|
| VDI | 服务器 | 瘦终端 | 不能 |
| IDV | 本地终端 | 胖终端 | 能 |
| VOI/TCI | 本地（从网络启动） | 胖终端 | 能 |

::: notes
VDI 安全性高、管理集中、支持移动办公，但依赖网络；IDV、VOI/TCI 性能好、可离线，但移动性和安全性较差。云计算应用仍以 VDI 为主。
:::

## 动画：三种桌面云架构

!sim vdi-arch
- 切换三种架构，看画面和数据在哪里
- 模拟断网，看哪种还能继续用

## 桌面云的应用场景

- **教育**：机房统一管理，一键还原
- **医疗**：诊室终端，病历数据不落地
- **金融**：柜台终端，安全合规
- **企业**：移动办公，换电脑不换桌面

# 本讲小结

## 本讲要点

- SDN 集中控制，Overlay 叠加虚拟网络
- VPC 是自己的隔离网络，弹性 IP 是可换绑的公网地址
- 云安全责任共担，问题多源于配置错误和权限管理
- 安全组是云服务器的第一道门卫
- VDI 云端算、安全集中，IDV、VOI/TCI 本地算、可离线
